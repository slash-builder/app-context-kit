# Contributing

The App Context Kit is a small library with one written contract and two implementations. The contract is [`spec/APP-CONTEXT.md`](spec/APP-CONTEXT.md) plus the shared fixtures in [`spec/conformance/`](spec/conformance/); the Dart core (`dart/app_context_kit`) and the Rust crate (`rust/`) must both pass every fixture. A Flutter companion (`dart/app_context_kit_flutter`) holds what the pure-Dart core cannot do. Read the [overview](docs/OVERVIEW.md) and [design decisions](docs/DESIGN-DECISIONS.md) first; they say what the Kit is for and what it deliberately is not.

## Build and test

You need Dart 3 (the core asks for `^3.0.0`, the companion for `^3.5.0`), Flutter 3.24 or later (the docs were checked with 3.41.9), Rust 1.78 or later (the crate's `rust-version`; CI also tests current stable), and Python 3 for the fixture generator. Docker is optional, for the Linux script. Everything comes from pub.dev and crates.io; nothing outside this repository is needed.

```sh
# the Dart core (pure Dart)
cd dart/app_context_kit && dart pub get && dart analyze && dart test

# the Flutter companion
cd dart/app_context_kit_flutter && flutter pub get && flutter analyze && flutter test

# the Rust crate
cd rust && cargo fmt --check && cargo clippy --all-targets --all-features -- -D warnings && cargo test

# the same two cores on Linux, in throwaway containers (needs Docker)
tools/linux-test.sh
```

The examples under `docs/examples/` are tested too: `dart test` in `dart_cli`, `coordination`; `flutter test` in `flutter_hello`; `cargo run` in `rust_cli`. The real-daemon and pinned-TLS tests in the Dart core skip unless their environment variables are set (they need a compatible Venue daemon, which is not part of this repository); a skipped run proves nothing about them. [docs/TESTING.md](docs/TESTING.md) has every command, the expected counts and how to add a fixture.

## Rules

1. **The spec and the fixtures are the contract.** If the prose and a fixture disagree, the fixture wins and the prose is corrected. Fixtures are generated by `tools/gen_fixtures.py`, whose expectations are spelled out by hand; an implementation never computes them. After you change it, run it and update the case counts that `rust/tests/conformance.rs` asserts.
2. **A change in behaviour needs a fixture or a test.** Pure behaviour (manifest rules, path resolution, modes) belongs in a fixture so both languages check it. Behaviour that touches the outside world (files, the roster, the Venue session, peers) belongs in a test in the language that implements it.
3. **Run both languages' suites** before you send a change, and say which commands you ran and what they printed. If a rule changes, both implementations change.
4. **The Kit never interprets an app's payload.** Coordination is an app-defined hook; the Kit finds, connects and routes bytes. A change that makes the Kit read or depend on what a message means is out of scope.
5. **The core stays pure Dart.** `dart/app_context_kit` has no Flutter import. Anything that needs Flutter goes in the companion.
6. **Apps compose the Kit and never fork it.** An app that needs something the Kit lacks writes it in the app and marks it `// KIT GAP:`. Build a Kit piece when a second app has written the same thing, not before.
7. **Say what was and was not verified.** A claim in the docs needs a test, a command or a measurement; otherwise it says "reasoned, not tested".
8. **No secrets and no machine-specific paths.** Tokens, hostnames and home directories do not belong in the tree. Tests that need a daemon read its address and token from the environment and skip without them.

## Sign your commits (DCO)

This project uses the [Developer Certificate of Origin 1.1](https://developercertificate.org/). By adding a `Signed-off-by` line you certify that you wrote the change or have the right to submit it under the project's licence (Apache-2.0).

```sh
git commit -s -m "your message"      # adds: Signed-off-by: Your Name <you@example.com>
git rebase --signoff main            # add the line to commits you already made
```

Use your real name and a working email address. A check on every pull request fails if any non-merge commit is missing the line. Under section 5 of the Apache License 2.0, a contribution you submit is licensed under the same terms as the project unless you state otherwise. There is no separate contributor agreement.

## Continuous integration

Every pull request runs formatting, clippy, docs, tests on Linux (x86-64 and arm64), macOS and Windows, the MSRV check, `cargo-deny` (advisories, licences, sources), a hygiene check, the Dart core and the Flutter companion. A release is a tag `vX.Y.Z` equal to the crate version; it publishes the Rust crate to crates.io by trusted publishing, from a protected environment.

## Conduct and security

By taking part you agree to follow the [Code of Conduct](CODE_OF_CONDUCT.md). A vulnerability is reported privately, as the [Security policy](SECURITY.md) says, never in a public issue.
